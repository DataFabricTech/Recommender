# 목적

- 가공된 데이터에서 메타데이터를 이용하여 임베딩 알고리즘을 응용한 데이터 플드별 유사도 측정 알고리즘 개발
- 데이터간 융합 추천 모듈 개발
- 추출한 메타 데이터를 유형 별로 자동 군집 분류 하여 데이터 검색 및 연계/추론에 활용

---

## 임베딩 알고리즘에서 사용되는 언어 모델

### 중요점

**한국어와 범용성에 대한 강점이 있는 임베딩 알고리즘에서 사용할 언어 모델의 필요성**

- KorBERT
- KoBERT
- KcBERT
- KLUE-BERT

#### 언어 모델 설명

**KcBERT**

- 학습 데이터: 한국어 소셜 미디어 및 댓글 데이터
- 목적 : 비공식적인 한국어 텍스트, 특히 소셜 미디어에서 사용되는 비격식적이고 다양한 표현을 이해하는데 중점
- 제작자 : Beomi

**KoBERT**

- 학습 데이터: 한국어 위키백과 및 뉴스데이터
- 목적 : 한국어의 다양한 태스크(텍스트 분류, 질의응답 등)을 처리학 위한 범용적인 BERT 모델
- 제작자 : SK텔레콤

**KorBERT**

- 학습 데이터 : 네이버에서 제공하는 뉴스, 도서 및 블로그 데이터를 기반으로 학습
- 목적 : 네이버의 검색, 질의응답 시스템 등 한국어 관련 여러 태스크
- 제작자 : 네이버

**KLUE-BERT** 

- 학습 데이터 : 한국어의 여러 도메인에서 수집된 대규모 데이터셋을 사용한 학습(한국어 위키백과, 뉴스, 쇼설 미디어 데이터, 기타 다양한 한국어 텍스트)
- 목적 : 한국어 언어 이해 태스크 전반에 걸쳐 성능을 테스트하기 위한 벤치마크 모델로 개발, 범용적으로 다양한 한국어 태스크에서 성능을 보여줄 수 있도록 설계
- 제작자 : Naver, Kakao, LG AI Research 등의 한국 AI 커뮤니티 협력 프로젝트

---

## KLUE-BERT를 선택한 이유

- 쇼셜 미디어 데이터에서 사용하는 데이터와 사전, 뉴스 등에서 사용하는 데이터 모두를 사용하여 만든 BERT로써, 위의 네 가지의 언어 모델중에 가장  범용성이 높은  KLUE-BERT를 선택하였습니다.

- 우선 사항
  - 광범위한/다양한 도메인
- 우대 사항
  - 비정형 데이터 - 따로 하는 것이 좋아 보인다.
  - 정형 데이터(Table)

- 제외 이유
  - UCI Machine Learning Repository
    - 최신 도메인에 미흡
  - MetaTables
    - 좁은 도메인 폭 및 도메인 다양성이 낮음
  - DBPedia
    - 데이터 전처리의 필요성
  - ClariQ Dataset
    - 텍스트 기반의 데이터셋
    - 데이터 전처리의 필요성
  - KDD Cup Datasets
    - 제한적인 데이터셋

- 선택 이유
  - Kaggle Datasets
    - 데이터 셋 품질이 일정하지 않지만, 사용자 리뷰 및 커뮤니티 지원을 통하여 개선될 것이라는 생각과, 최신 도메인의 유입이 원할 할 것으로 보임
    - 특정 도메인이 없는 경우에, 사용자가 도메인을 만들 수 있다는 장점
    - 포맷이 다양하다는 단점은, 반대로 사용자의 입맛대로 도메인을 구성할 수 있다는 장점으로 변경 가능
