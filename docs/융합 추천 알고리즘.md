# 목적

- 기준 데이터와 **조인해서 함께 쓸 수 있는** 데이터를 추천
- 두 데이터 사이에서 조인 키가 될 수 있는 컬럼 쌍을 찾고, 관계 유형을 판정

# 기존 추천과 무엇이 다른가

클러스터링·임베딩 추천은 **내용이 비슷한 데이터**를 찾습니다. 유사도가 높을수록 좋은 추천입니다.

융합 추천은 방향이 반대입니다. 회원 데이터와 거의 같은 회원 데이터를 조인해도 얻는 정보가 없습니다. **서로 다른 데이터를 연결할 수 있는지**가 기준이므로, 유사도만으로는 판정할 수 없습니다.

| 구분 | 클러스터링·임베딩 추천 | 융합 추천 |
|---|---|---|
| 찾는 것 | 내용이 비슷한 데이터 | 조인 가능한 데이터 |
| 판정 단위 | 데이터(테이블) 전체 | **컬럼 쌍** |
| 좋은 결과 | 유사도가 높음 | 연결은 되지만 **내용은 겹치지 않음** |

# 판정 근거를 여러 개 쓰는 이유

컬럼 쌍이 조인 키인지는 하나의 근거로 정할 수 없습니다. 세 가지를 함께 봅니다.

| 근거 | 무엇을 보는가 | 단독으로 쓸 수 없는 이유 |
|---|---|---|
| **값 도메인 겹침** | 두 컬럼의 상위 빈도값이 얼마나 겹치는가 | 표본이 도메인을 대표하지 못하면 판정할 수 없습니다. 고유값이 매우 많은 키(UUID 등)는 표본 겹침이 거의 0이 됩니다 |
| **카디널리티 패턴** | 한쪽이 고유값에 가깝고 다른 쪽이 반복되는가 (PK-FK 형태) | 통계표의 집계 수치끼리도 이 패턴이 나옵니다 |
| **컬럼명 근거** | 표기 유사도와 의미 유사도 | 이름이 같아도 의미가 다른 경우가 많습니다 (`구분`, `유형` 등) |

## 컬럼명 근거를 하나로 묶는 이유

표기 유사도와 의미 유사도를 **별도 근거로 세지 않습니다.** 같은 문자열에 대한 두 측정이므로 독립적인 증거가 아닙니다. `구분 = 구분`은 표기도 의미도 완전히 일치하지만 증거는 하나입니다.

두 측정 중 **큰 값**을 이름 근거로 삼습니다. 서로 보완하는 탐지 수단이기 때문입니다 — 표기 유사도는 영문 약어에 강하고, 의미 유사도는 한글 동의어에 강합니다.

## 확신 계수

근거 중 일부만 판정 가능한 경우가 많습니다. 값 겹침을 못 쟀다고 해서 나머지 근거만으로 같은 점수를 주면, **근거가 적을수록 점수가 쉽게 올라갑니다.**

그래서 점수에 **사용한 근거의 비중**을 반영합니다. 세 근거를 모두 쓴 판정이 이름만 맞는 판정보다 높은 확신을 갖습니다.

# 오탐을 거르는 장치

조인 가능성 점수만으로는 아래 경우를 걸러내지 못합니다. 별도 판정을 둡니다.

| 거르는 대상 | 근거 |
|---|---|
| **행번호 컬럼끼리** | 양쪽 모두 표별 순번이면 값이 겹쳐도 조인 근거가 없습니다 |
| **집계 수치 컬럼끼리** | 작은 정수 집합은 통계표 집계값의 특징입니다. 값이 같아도 의미가 다릅니다 |
| **시스템 컬럼** | 적재기가 덧붙인 컬럼은 원천 데이터의 속성이 아닙니다 |
| **피벗 자리표시자** | 피벗 테이블의 열 이름은 데이터가 아니라 표의 구조입니다 |
| **구성이 거의 같은 테이블** | 컬럼 구성이 중복되면 조인해도 정보 이득이 없어 점수를 낮춥니다 |
| **흔한 컬럼명** | 여러 테이블에 공통으로 나타나는 이름은 근거로서의 가치가 낮아 가중치를 낮춥니다 |

# 관계 유형 판정

고유값 비율로 판정합니다.

| 패턴 | 판정 |
|---|---|
| 양쪽 모두 고유값에 가까움 | 1:1 |
| 한쪽만 고유값에 가까움 | 1:N |
| 양쪽 모두 반복 | 조인 키로 보지 않습니다 |

# 결과

점수가 기준 미만인 쌍은 추천하지 않습니다. 테이블 단위 점수는 컬럼 쌍 점수를 종합해 산출하며, 조인 근거가 된 컬럼 쌍을 함께 응답에 담아 **왜 추천되었는지** 확인할 수 있게 합니다.

파라미터(가중치·기준값)는 별도 검증셋으로 조정했습니다.
